## 1) هدف محصول
پلتفرم واحد خدمات کلینیک رز — نه فقط وب‌سایت یا نوبت‌دهی ساده:
- مراجع: یافتن مشاور/شعبه، رزرو، پرداخت، اعلان، دسترسی کنترل‌شده به سوابق و فایل‌های مجاز
- کلینیک: مدیریت شعب، مشاوران، صلاحیت‌ها، تعرفه‌ها، نوبت‌ها، پرداخت‌ها، پرونده‌ها، گزارش‌ها
- آموزش: فروش دوره، آزمون، گواهی
- بالینی: پرونده دیجیتال با محرمانگی، رضایت‌نامه، تست روان‌شناسی با تفسیر مصوب
- AI: فقط کمکی و تحت نظارت متخصص — خودمختار نیست

ارزش‌ها: عملیاتی (کاهش ثبت دستی، جلوگیری رزرو تکراری) · تجاری (معرفی آنلاین، درآمد دوره) · حرفه‌ای (پرونده کنترل‌شده) · حاکمیتی (رضایت آگاهانه، ردگیری، حسابرسی)

## 2) فناوری‌های الزامی سند
| لایه | الزام |
|---|---|
| Backend | Python / FastAPI؛ Pydantic؛ OpenAPI از کد؛ SQLAlchemy + Alembic؛ صف کار پس‌زمینه؛ الگوی Outbox برای رویداد مالی/اعلانی؛ request-id و لاگ ساختاریافته و health check |
| Database | PostgreSQL؛ شناسه بر اساس ADR-01؛ timestamptz و UTC؛ FK/unique/check/ایندکس؛ قید جلوگیری از رزرو متداخل و ثبت مالی تکراری؛ نسخه‌گذاری تعرفه/محتوا/آزمون/تفسیر/رضایت؛ schemaها: `core`, `booking`, `clinical`, `finance`, `content`, `edu`, `audit` |
| Frontend | React / Vite؛ پنل مراجع/مشاور/پذیرش/ناشر/مدیریت؛ RTL و فارسی؛ تاریخ شمسی فقط در UI |
| Mobile | Flutter (انتشار 2)؛ API مشترک نسخه‌دار؛ ذخیره حداقلی حساس؛ توکن در فضای امن OS؛ Push با احترام به ترجیح کاربر |
| Delivery | Docker + Git + CI/CD؛ Reverse Proxy + TLS |
| Storage | فایل/ویدئو/PDF در Object Storage خصوصی؛ در DB فقط فراداده/مالکیت/مجوز/نسخه/checksum/کلید فایل |

جریان استقرار: مرورگر/Flutter ↔ Reverse Proxy+TLS ↔ FastAPI ↔ PostgreSQL ؛ FastAPI ↔ صف و Worker ↔ SMS/Email/رسانه ؛ FastAPI ↔ Object Storage

- API/DB: `/consents` `/consents/{id}/revoke` `/audit/access`؛ `consents, consent_versions, access_events`
- پذیرش: سابقه با نسخه و تاریخ؛ گزارش دسترسی غیرمجاز قابل استخراج — وابستگی: B02,B04

## 7) نقش‌ها و مجوزها
| نقش | اختیارات نمونه | محدودیت ضروری |
|---|---|---|
| بازدیدکننده | محتوای عمومی، مراکز، شعب، خدمات، نقشه | بدون پرونده، دوره پولی، نتیجه تست |
| مراجع/خریدار | پروفایل، رزرو، پرداخت، پیام/فایل خود، دوره‌های مجاز | فقط داده خود یا داده صریحاً اعطاشده |
| مشاور | تقویم، جلسات، پیام، پرونده مراجعان مجاز | عدم دسترسی خودکار به همه پرونده‌ها/تست‌ها |
| پذیرش شعبه | ثبت مراجع، زمان‌بندی، پیگیری نوبت شعبه | بدون یادداشت درمانی مگر مجوز مصوب |
| مدیر شعبه | خدمات و گزارش عملیاتی شعبه | محدود به شعبه و حداقل داده |
| مدیر محتوا/آموزش | مقاله، خبر، رسانه، دوره، آزمون آموزشی | بدون داده درمانی و نتایج تست |
| مالی | سفارش، فاکتور، استرداد، تسویه | بدون جزئیات محرمانه جلسه |
| مدیر سامانه | نقش، تنظیمات، پایش، ممیزی | بدون دسترسی درمانی پیش‌فرض |
| ناظر علمی | تأیید محتوای حساس، کلید تست، متن تفسیر | انتشار فقط با نسخه/تصمیم/تاریخچه |
| حسابرس/DPO | لاگ، گزارش انطباق، درخواست حذف داده | بدون محتوای درمانی متنی |

## 8) قواعد سراسری اعتبارسنجی
- هر فیلد: ضروری/سقف طول/قالب/یکتایی/پیام خطای مشخص
- زمان سرور منبع حقیقت؛ UI شمسی فقط نمایشی
- موبایل نرمال‌سازی واحد و یکتا در موارد لازم
- ویرایش موجودیت منتشرشده، داده تاریخی را بی‌اعتبار نکند
- وضعیت‌های قابل انتقال (سفارش، نوبت، فایل، آزمون، استرداد) مستند شوند
- حذف داده درمانی فقط با سیاست نگهداری مصوب + ثبت رخداد

## 9) سه مفهوم آموزشی متفاوت (نباید یکی گرفته شوند)
- **پرسشنامه پرونده:** جمع‌آوری داده مرتبط با مشاوره (B14)
- **آزمون دوره:** سنجش یادگیری و صدور گواهی (B36)
- **تست روان‌شناسی:** سنجش و تفسیر حرفه‌ای با کنترل علمی (B37)
